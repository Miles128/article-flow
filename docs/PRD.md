# Article Flow PRD

版本：v1.3  
日期：2026-06-30  
状态：基于 README、当前代码结构与用户反馈整理  
适用范围：Article Flow 桌面端与 Web 开发版

## 1. 背景与问题

自媒体内容生产是一条从选题、资料、写作、审校、格式、配图到发布准备的连续链路。创作者的实际困难不只是生成文字，而是把一个选题稳定推进成可发布、可复用、可追踪的内容资产。

当前阶段最需要解决的是选题已确定或大致确定之后的生产问题：

- 资料、主张、大纲和草稿分散，难以形成统一上下文。
- AI 生成或改写后的内容容易出现套话、结构松散、事实风险和风格不统一。
- 草稿修改缺少版本保护，重要内容容易被覆盖。
- 标题、摘要、封面文案、格式、配图和发布包需要重复手工整理。
- 发布前缺少可解释的质量检查和风险提示。

Article Flow 要在长期上支持完整创作链路，在短期上优先把“题目已定后”的内容工作台做好。

## 2. 产品定位

Article Flow 是面向个人内容创作者的本地优先自媒体内容全流程工作流平台。

产品长期覆盖从选题发现到发布准备的完整流程，包括热搜选题、确定选题、资料搜集、大纲规划、草稿写作、标题与发布文案、修改审核、平台格式适配、配图生成和发布准备。

当前阶段的建设重点是题目已定或已有草稿后的内容生产工作台：

- 围绕草稿组织资料、大纲、版本、风格、审核、格式、配图和发布包。
- 支持用户跳过不需要的步骤，从已有题目、已有资料、已有大纲或已有草稿进入。
- 保留热搜和选题能力作为全流程入口，但短期不重点完善复杂热点发现能力。

明确不做：

- 多人协作 CMS。
- 云端内容管理平台。
- 自动发文系统。
- 事实准确性担保系统。
- 强制用户线性走完所有步骤的流程软件。

## 3. 目标用户与场景

目标用户：

- 公众号、知乎、今日头条等长文作者。
- 小红书、即刻等短内容创作者。
- B 站、播客、短视频口播稿创作者。
- 需要围绕热点、经验、观点、教程、评测或解读持续产出的个人创作者。

高优先级场景：

- 用户已有题目，需要补资料、搭大纲、写正文。
- 用户已有草稿，需要润色、去 AI 味、审校、改标题和准备发布包。
- 用户已有资料，需要提炼观点、主张、大纲和写作角度。
- 用户需要把同一母稿适配到多个发布平台。
- 用户需要快速生成封面文案、配图 brief 或 HTML 配图。

低优先级场景：

- 用户还没有题目，需要系统从全网热点里发现方向。
- 用户要长期监控竞品、热点、榜单和趋势。
- 用户需要多人协作、云端同步或自动发布。

## 4. 产品目标

长期目标：

- 成为个人创作者从选题到发布准备的全流程内容操作台。

当前阶段目标：

- 跑顺题目已定后的内容生产链路。
- 让草稿、资料、主张、大纲、版本、标题、配图和发布包成为可恢复的本地项目资产。
- 降低 AI 辅助写作后的修稿、查证、去 AI 味和平台适配成本。
- 在发布前提供可解释的质量门禁和导出结果。

建议成功指标：

- 已有题目创建项目后完成草稿的比例。
- 导入或生成草稿后进入发布准备的比例。
- 从创建项目到导出发布包的耗时。
- AI 味检测通过率、修复次数和版本恢复次数。
- 发布门禁失败后的修正完成率。
- 用户重复使用工作区、风格配置和平台格式的频率。

## 5. 产品原则

### 5.1 全流程定位，阶段性建设

产品定位保持全流程，但开发优先级服务当前阶段主路径。热搜和选题能力保留入口，不牵引短期核心设计。

### 5.2 草稿是当前主资产

短期内，第 5 步草稿是系统最重要的内容资产。资料、大纲、标题、审核、格式、配图和发布包都围绕草稿展开。

### 5.3 步骤是入口，不是强制关卡

用户可以跳过任意前置步骤。系统提供缺失提示和能力降级，而不是阻断流程。

### 5.4 上下文优先于单点 AI 按钮

AI 功能应优先利用项目上下文，包括题目、资料、主张、大纲、风格档案、历史版本和平台目标。

### 5.5 风险必须可解释

AI 味、事实风险、合规风险、格式风险和发布门禁都应说明失败原因、影响范围和可修正方向。

### 5.6 本地优先

默认不依赖外部数据库。项目资产存储在本地 JSON 和工作区文件中，优先满足个人创作者的隐私、可迁移和低运维需求。

## 6. 范围与优先级

当前阶段必须跑顺：

- 创建项目时可输入题目或导入草稿。
- 可跳过热搜和复杂选题管理。
- 可补充资料、运行深度分析、登记主张。
- 可生成或编辑大纲。
- 可写作、续写、改写、去 AI 味和保存版本。
- 可生成标题、摘要、封面文案和结尾互动。
- 可审校、评论、修正。
- 可做平台格式适配。
- 可生成配图 brief 或 HTML 配图。
- 可执行发布门禁并导出发布包。

保留但不重点完善：

- 热搜选题。
- 候选选题池。
- 基础选题评估。
- 从热搜结果创建候选选题。

后续可增强：

- 竞品话题扫描。
- 趋势和受众评估。
- 选题到写作 brief 的自动转化。
- 自动发布或半自动发布。
- 平台表现回填。
- 内容复盘和选题学习。
- 多端同步。
- 团队协作。

## 7. 工作流

长期完整工作流：

| 步骤 | 名称 | 说明 | 当前优先级 |
| --- | --- | --- | --- |
| 1 | 热搜选题 | 多平台热搜聚合、热点趋势分析、智能选题挖掘 | 低 |
| 2 | 确定选题 | 多维评估、选题卡片管理、状态追踪 | 中 |
| 3 | 搜集资料 | 多源采集、深度分析、主张登记、来源核查 | 高 |
| 4 | 列出大纲 | AI 生成、章节类型标记、大纲编辑 | 高 |
| 5 | 写出草稿 | 按节写作、多模式、去 AI 味检测、版本管理 | 高 |
| 6 | 标题工坊 | 标题、副标题、封面文案、摘要、钩子 | 高 |
| 7 | 修改审核 | 内容、风格、细节、真实性、合规、逻辑检查 | 高 |
| 8 | 格式处理 | Markdown 规范化、多平台格式适配 | 高 |
| 9 | 生成配图 | 配色、比例、HTML 配图、图片提示词 | 中 |
| 10 | 发布准备 | 发布清单、质量门禁、发布包、ZIP 导出 | 高 |

跳过规则：

- 没有热搜：不影响后续流程。
- 没有选题对象：项目标题可作为临时主题。
- 没有资料：允许写作，但深度分析、主张核查和引用能力不可用或提示缺失。
- 没有大纲：允许直接写草稿，按节写作降级为整体写作。
- 没有草稿：标题、审核、格式、配图和发布准备提示先导入、生成或填写正文。
- 发布导出：执行质量门禁，失败时默认阻止，用户可显式 force 导出。

## 9. 功能需求

### 9.1 项目与工作区

- 支持项目创建、列表、详情、更新、删除。
- 创建项目时支持输入题目、选择内容类型、目标字数和工作区。
- 支持从已有 Markdown 或纯文本导入草稿。
- 支持本地工作区路径记忆、Markdown 扫描和标准 ZIP 导出。
- 删除项目时清理关联的选题、资料、主张、大纲、草稿、评论和版本。

### 9.2 热搜与选题

- 支持基础分类、搜索和从结果创建候选选题。
- 支持候选选题增删改查。
- 支持 selected、pending、rejected 状态。
- 支持简单 AI 评估作为参考。
- 不在当前阶段重点投入复杂趋势分析、榜单聚合、热点评分、自动竞品监控和选题推荐闭环。
- 用户可直接用项目标题作为主题；没有 selected 选题时，写作上下文使用项目标题或用户输入主题。

### 9.3 资料、深度分析与主张核查

- 支持网页、文本、文件或深度分析报告作为资料。
- 支持安全抓取 URL、提取正文、摘要、关键词和引用格式。
- 支持“联网搜索 + 项目资料”的深度分析，输出结构化报告、写作角度、建议主张和大纲节点。
- 支持主张登记、删除和 AI 辅助核查。
- 没有资料时可以直接写作。
- 高风险内容应提示补充资料和核查，包括事实、数据、法律、医疗、财经等内容。

### 9.4 大纲

- 支持项目维度的大纲读取、生成、保存和编辑。
- 大纲节点支持标题、内容、层级、子节点和章节类型。
- 支持信息型和经验型章节标记。
- 写作阶段可将大纲转换为 Markdown 上下文。
- 没有大纲时允许整体写作、导入草稿或自由编辑。
- 按节写作依赖大纲；缺少大纲时相关能力降级。

### 9.5 写作与草稿

- 草稿默认存储在第 5 步。
- 写作上下文优先组合已选题目、大纲和资料摘要；缺失项自动跳过。
- 支持续写、润色、扩写、精简、风格转换、自定义提示词、流式写作、按节写作和整体草稿生成。
- 支持写作模式、写作意图、风格配置、强度控制和风格样本。
- 支持 AI 味规则扫描、自动修复、得分展示和命中解释。
- 支持草稿版本快照、列表、查看和恢复。
- 第 6 步及之后的模块默认读取第 5 步草稿。
- 保存已有草稿前应自动留档，避免覆盖重要版本。
### 9.6 标题与发布文案

- 支持基于草稿生成标题候选。
- 支持副标题、封面文案、摘要、开头钩子和结尾互动问题。
- 支持保存选定标题、封面文案和发布相关文案。
- 发布文案可作为结构化 JSON 内容保存。
- 没有标题工坊结果时，发布包使用项目标题。
- 没有摘要时，可从正文前 120 字生成短摘要。

### 9.7 审核与评论

- 支持内容、风格、细节、真实性、合规、逻辑和工作区规则检查。
- 支持单轮审校、全量审校和审校流水线。
- 支持评论创建、更新、删除、回复和解决状态。
- 审核不是进入格式或配图的前置条件。
- 发布前质量门禁仍应独立运行。
### 9.8 格式处理

- 支持 Markdown 规范化。
- 支持公众号、知乎、小红书、B 站专栏、简书、今日头条等平台适配。
- 支持内联 CSS、HTML 或文件导出能力。
- 用户只需要母稿时可跳过平台格式。
- ZIP 导出应尽量包含母稿和可生成的平台格式。
### 9.9 配图生成

- 支持多套预设配色和自定义配色。
- 支持 3:4、9:16、4:3、16:9、1:1、2:3 等比例。
- 支持基于内容生成图片提示词、HTML 配图和打印 PNG。
- 配图不是发布包导出的硬依赖。
- 缺少配图时发布包中 `imageBriefs` 可为空。
### 9.10 发布准备

- 发布包包含版本、导出时间、项目 ID、标题、钩子、摘要、正文、结尾问题、封面文案、配图 brief 和质量结果。
- 发布前执行 AI 味和内容质量门禁。
- 门禁失败时默认拒绝导出，返回可解释原因；用户可显式 force 导出。
- ZIP 导出根目录为 `article-flow-export/`。

## 12. 非功能需求

本地数据与可靠性：

- 默认数据目录为后端 `data/`，可通过 `ARTICLE_FLOW_DATA_DIR` 覆盖。
- JSON 写入采用临时文件加原子替换。
- 每个集合有读写锁，降低并发读写风险。
- 检测 JSON 损坏时备份损坏文件，避免静默覆盖。

安全：

- URL 抓取必须做 SSRF 防护。
- 单次抓取和总结内容必须有最大长度限制。
- LLM API Key 通过 `.env` 配置，不提交仓库。
- 错误信息应转为用户可理解提示，避免泄露堆栈。

性能与体验：

- 常规 API 请求目标 30 秒内返回。
- 深度分析、大纲生成、长文写作可设置更长超时或使用流式返回。
- AI 长任务需要清晰的加载、失败、取消和重试状态。

测试：

- 后端使用 pytest。
- 前端使用 Vitest。
- 核心覆盖：AI 味检测、文章格式化、深度分析、草稿版本、写作意图、风格转换、SSRF 防护、发布门禁。

## 15. 非目标

当前阶段非目标：

- 不重点完善热搜选题。
- 不要求用户必须从热搜或选题管理开始。
- 不要求用户必须完成所有步骤。
- 不做复杂趋势分析、榜单聚合、热点评分和自动竞品监控。

长期非目标：

- 不做团队权限管理，除非产品明确转向协作。
- 不承诺联网资料的绝对真实性。
- 不把 AI 输出直接作为最终稿强制发布。
- 不引入外部数据库作为默认依赖。

## 16. 验收标准

基础运行：

- 后端可通过 `cd backend && uv sync && uv run python run.py` 启动。
- 前端可通过 `cd frontend && npm run dev` 启动。
- `GET /api/health` 返回 `status: ok`，并展示 LLM 是否已配置。

主路径：

- 用户可以创建文章型项目，并用项目标题作为题目进入工作台。
- 用户可以跳过热搜和候选选题，直接导入或编辑草稿。
- 用户可以补充资料、运行深度分析、登记主张并生成大纲。
- 用户可以没有资料或大纲时继续写作，并看到能力降级提示。
- 用户保存草稿后，标题、审核、格式、配图和发布准备能读取草稿。
- 没有草稿时，后续模块能提示导入、生成或填写正文，而不是静默失败。

质量与发布：

- AI 味检测返回得分、命中项、维度和建议。
- AI 味修复展示前后分数。
- 发布导出前执行门禁；失败时默认拒绝并返回原因。
- 发布包包含标题、正文、摘要、封面文案、配图 brief 和质量信息。
- ZIP 导出包含标准目录 `article-flow-export/`。

测试：

- 后端 `pytest` 通过。
- 前端 `npm test` 通过。
- 若修改 Tauri 壳或桌面权限，手动验证 `npm run tauri:dev`。

## 17. 风险与待澄清

产品风险：

- 全流程叙事容易让当前阶段建设范围失焦。
- 如果 UI 强展示 10 步线性流程，会和真实创作过程冲突。
- 热搜入口如果过重，会把当前阶段产品带偏到找题工具。
- 去 AI 味评分如果解释不足，会被用户视为黑箱。
- 深度分析依赖联网搜索和 LLM，稳定性受外部服务影响。

技术风险：

- 本地 JSON 不适合多人协作、大规模数据和复杂查询。
- AI 长任务需要更稳定的流式体验、取消机制和错误恢复。
- Tauri、Next.js、Flask 三进程开发链路增加上手成本。

待澄清：

- UI 是否保留 10 步导航，同时减少线性强迫感？
- 项目创建页是否提供“已有题目”“已有草稿”“从热搜找题”三个入口？
- 发布包 schema 是否需要稳定版本和迁移策略？
- 工作区规则是否应进入发布门禁？
- AI 味目标分数是否按平台和内容类型区分？
- 是否统一 `doc/` 与 `docs/` 目录，避免文档分散？
